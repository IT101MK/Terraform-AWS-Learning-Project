Your complete walkthrough for building (and safely destroying) your first real AWS environment with Infrastructure as Code. Follow it top to bottom — every command is copy-paste ready for PowerShell.

1 What you're building

A small but real AWS environment — the same building blocks used in production, minus the complexity.

Infrastructure as Code (IaC) means describing cloud resources — servers, networks, storage — in text files instead of clicking around a web console. Terraform reads those files, compares them to what actually exists in AWS, and creates/updates/deletes resources to match. Your infrastructure becomes repeatable, reviewable (it's just code), and disposable — destroy everything and rebuild it identically in minutes.

ResourceWhat it's for
VPC 10.0.0.0/16Your own isolated network inside AWS
Public subnet 10.0.1.0/24The slice of the network where the server lives
Internet Gateway + route tableConnects the subnet to the internet (this is what makes it "public")
Security groupFirewall: HTTP (80) from anywhere, SSH (22) from your IP only
EC2 instance (t3.micro)Amazon Linux 2023 server that installs nginx and serves a hello page
IAM role + instance profileLets the server access ONE S3 bucket — no passwords or keys stored anywhere
Private S3 bucketObject storage the server can read/write (random name suffix — bucket names are global)
Tip: cost is £0 if you stay in the Free Tier and destroy when done. t3.micro is free for 750 hrs/month during your account's first 12 months. There is deliberately no NAT Gateway or load balancer in this project — those are the classic "surprise bill" traps for learners.
Note: free-tier eligible instance types vary by account and region. Don't assume t2.micro — plenty of guides still do, but many accounts today are only eligible for t3.micro or t4g.micro. Check what your account actually qualifies for before setting instance_type: 
aws ec2 describe-instance-types --region us-east-1 --filters "Name=free-tier-eligible,Values=true" --query "InstanceTypes[].InstanceType" --output table

3 Prerequisites — one-time setup

Do these once, in order. Tick each box before moving to section 5.

  • Create an AWS account — aws.amazon.com/free. Enable MFA on the root account, then stop using root for daily work.
  • Set up a budget alert first (5 minutes, permanent peace of mind): AWS console → Billing → Budgets → Create budget → Zero spend budget (or £4/month, approx.) with an email alert.
  • Create an IAM user for Terraform: console → IAM → Users → Create user → attach AdministratorAccess (fine for a personal learning account) → create an access key (choose "Command Line Interface"). Save the Access Key ID + Secret. Enable MFA on this user too — an admin user with leaked keys and no MFA is the classic account-takeover story, and you know this drill from Entra.
  • Install & configure the AWS CLI (see commands below).
  • Install Terraform (see commands below).
  • Find your public IP — open checkip.amazonaws.com and note it down. You'll need it in step 5.1.

Install commands (PowerShell)

# --- AWS CLI ---
winget install Amazon.AWSCLI
# restart your terminal, then:
aws configure
# paste Access Key ID, Secret Access Key, region: us-east-1, output: json
aws sts get-caller-identity   # sanity check — shows your account/user

# --- Terraform ---
winget install Hashicorp.Terraform
# restart your terminal, then:
terraform version
Warning: restart your terminal after each install Newly installed programs aren't on your PATH until you open a fresh PowerShell window. If aws or terraform says "not recognized", that's why.

4 The Terraform workflow

Every Terraform session follows this cycle. Memorize it — it's the same at every job.

5 Build it, step by step

All commands run in PowerShell from the project folder. Start every session with:

cd Project-IaC
5.1

Create your personal variables file

Copy the template, then edit it with your own values:

Copy-Item terraform.tfvars.example terraform.tfvars
notepad terraform.tfvars

Set ssh_allowed_cidr to your public IP + /32 (from checkip.amazonaws.com), e.g. "198.51.100.7/32". Leave everything else as-is for now.

Note: why /32? A /32 means "exactly this one IP address" — so only your computer can even attempt SSH. The project refuses 0.0.0.0/0 (the whole internet) on purpose. This file is git-ignored because it's personal to you.
5.2

Initialize the project

Downloads the AWS and random providers into .terraform/. Run once per project (again only if provider versions change):

terraform init

Success looks like: "Terraform has been successfully initialized!"

5.3

Format and validate

Good habits from day one — format the code, then catch errors before touching AWS:

terraform fmt        # auto-formats .tf files to canonical style
terraform validate   # catches syntax/reference errors
5.4

Plan — the dry run

Terraform shows exactly what it would create. Nothing is built yet.

terraform plan

Look for this at the end: Plan: 13 to add, 0 to change, 0 to destroy.

Tip: always read the plan. This habit will save you at work. The plan is Terraform telling you its intentions — + means create, ~ means change, - means destroy. Never apply a plan you haven't read.
5.5

Apply — build it for real

terraform apply

Terraform shows the plan again and asks for confirmation — type yes. After 2–3 minutes you'll see the outputs:

Outputs:

bucket_name        = "tf-learning-data-a1b2c3d4"
instance_public_ip = "3.85.x.x"
website_url        = "http://3.85.x.x"
ssh_command        = "No key pair configured - set key_pair_name in terraform.tfvars to enable SSH (see README)."

Note: ssh_command only shows a real SSH command once you've set key_pair_name — see section 8. Until then it prints the reminder above, which is expected.

6 Verify it worked

Three ways to prove your infrastructure is real.

  1. Open the website — copy the website_url output into your browser. You should see "Hello from Terraform!". Give it a minute or two after apply — the boot script needs time to install nginx.
  2. Check the AWS console — EC2 → Instances (region: us-east-1): you'll see tf-learning-web running. Also peek at VPC → Your VPCs and S3 → Buckets. Everything is tagged Project = terraform-learning.
  3. Re-print outputs anytime: terraform output
Warning: it's http://, not https:// Browsers sometimes silently force https:// and show a connection error. Check the address bar — this simple server only speaks plain HTTP on port 80.

7 Troubleshooting & lessons learned

Real errors hit during this build, with the root cause and the fix — a reference for when things don't go to plan.

SymptomCauseFix
InvalidParameterCombination: instance type not eligible for Free Tier Free-tier eligible instance types differ by account and region and change over time. Older guides assume t2.micro, but many accounts today only get t3.micro or t4g.micro. Query what's actually eligible before setting instance_type:
aws ec2 describe-instance-types --region <region> --filters "Name=free-tier-eligible,Values=true" --query "InstanceTypes[].InstanceType" --output table
terraform plan -out errors with "flag needs an argument" or "is a directory" -out requires a filename, not a bare flag or a directory path. Give it a name explicitly: terraform plan -out=tfplan, then apply exactly that plan with terraform apply tfplan.
PowerShell says "term not recognized" for something that looks like a resource name or tag value Text describing what a config file should contain (e.g. key_pair_name = "my-key") is not a shell command — it's an instruction to edit a file, and PowerShell tries to run it literally. Open the file in a text editor and make the edit there: notepad terraform.tfvars. Don't type config syntax at the prompt.
Saved .pem private key file is 0 bytes, and AWS reports InvalidKeyPair.Duplicate on retry aws ec2 create-key-pair ... | Out-File keyname.pem truncates the file on every run — including failed or repeated runs. Running the create command a second time hits InvalidKeyPair.Duplicate and silently wipes the previously saved key. AWS never lets you retrieve a private key after creation, so the key pair becomes unusable at that point. Run the create command exactly once. To redo it, explicitly delete the old key pair first (aws ec2 delete-key-pair --key-name ...), remove the old .pem, then create fresh. Never re-run create-key-pair "just in case."
SSH connection times out to an IP that worked a moment ago Changing key_pair_name (or various other instance attributes) forces Terraform to destroy and recreate the EC2 instance, which gets a brand-new public IP. A browser tab can also appear to still "work" from cache even though the server behind that IP no longer exists. After any apply that replaces the instance, re-check terraform output for the current IP instead of reusing one from a previous session. Hard-refresh any browser tab pointed at the old IP.
Commands fail inside an SSH session on the instance — terraform or a familiar command "not found," or cp failing against an s3:// path SSH drops you into a separate Linux environment on the remote server, which has none of your local machine's tools. Terraform isn't installed there, and never needs to be — the whole point of the exercise is that the server only has the AWS CLI and its IAM role. Run Terraform commands (terraform output, terraform destroy, etc.) back on your own machine — exit the SSH session first. To copy files to/from S3, use aws s3 cp, not the plain cp command — S3 isn't a real filesystem path.
A command fails when placeholder text like <your-bucket-name> or <instance_public_ip> is copied in literally Angle brackets in a guide mark a placeholder to be replaced with your actual value, not literal text to type. Substitute the real value — shown in terraform output or on the deployed page — before running the command.

8 Optional: SSH in & see IAM least-privilege in action

The best lesson in this project: the server can use S3 with no stored credentials at all.

8.1

Create a key pair (PowerShell)

aws ec2 create-key-pair --key-name tf-learning-key --query 'KeyMaterial' --output text | Out-File -Encoding ascii tf-learning-key.pem

Then in terraform.tfvars, uncomment and set:

key_pair_name = "tf-learning-key"

Run terraform apply again.

Warning: the instance will be REPLACED Adding a key to an existing instance forces destroy + recreate (you get a new IP). The plan will say so — that's normal. Read it, confirm with yes.
8.2

SSH in

Windows 10/11 includes OpenSSH — no extra install needed:

ssh -i tf-learning-key.pem ec2-user@<instance_public_ip>
8.3

Test S3 access from the instance (you're now in a Linux shell)

The bucket name is shown on the hello page, or run terraform output bucket_name on your PC.

echo "hello from the instance role" > test.txt
aws s3 cp test.txt s3://<your-bucket-name>/test.txt   # works: role allows PutObject
aws s3 cp s3://<your-bucket-name>/test.txt back.txt   # works: role allows GetObject
aws s3 ls s3://<your-bucket-name>/                    # works: role allows ListBucket
aws s3 ls                                             # FAILS: listing ALL buckets is not granted
Tip: that last failure is the whole point — least privilege. The role can touch this one bucket and nothing else. No access keys exist on the instance — run aws sts get-caller-identity there and you'll see it's using the role. This "no credentials on servers" pattern is a top interview topic.

9 Destroy when you're done — every session

The single most important habit in this whole guide.

terraform destroy   # shows what will be deleted, asks for "yes"
Important: every session ends with destroy.
  • Free Tier covers 750 hours/month of an eligible micro instance type (e.g. t3.micro) for the first 12 months — but only on eligible accounts, and it expires. A forgotten micro instance after that is roughly £6–7/month (approx.).
  • Rebuilding is one terraform apply away — that's the whole point of IaC. Destroying costs you nothing but a coffee break.
  • You did set up that budget alert in section 3, right?
  • This is your AWS bill, your responsibility — only you can stop charges accruing on your account.

If you created the SSH key pair, it lives outside Terraform — delete it separately when you're fully done:

aws ec2 delete-key-pair --key-name tf-learning-key
Remove-Item tf-learning-key.pem

10 What each file does

Open them in this order — each one is heavily commented as teaching material.

FileContents
versions.tfRequired Terraform + provider versions (pinned for reproducibility)
providers.tfAWS provider config: region + default tags applied to everything
variables.tfInput variables with descriptions, defaults, and validation rules
network.tfVPC, subnet, internet gateway, route table, security group
compute.tfAMI lookup (data source) + the EC2 instance
user_data.sh.tplBoot script template: installs nginx, writes the hello page
iam.tfIAM role, least-privilege S3 policy, instance profile
storage.tfPrivate S3 bucket with random name suffix + public access block
outputs.tfValues printed after apply (IP, URL, bucket, SSH command)
terraform.tfvars.exampleTemplate for your personal values — copy to terraform.tfvars
.gitignoreKeeps state files, .terraform/, tfvars, and keys out of git
Note: files Terraform creates for itself terraform.tfstate — Terraform's record of what it built. Treat it as sensitive, never edit by hand. .terraform/ — downloaded providers. .terraform.lock.hcl — exact provider versions (this one should be committed to git).
